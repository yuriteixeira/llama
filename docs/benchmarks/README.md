# Benchmarks

This directory contains benchmark notes and raw outputs for the local `llama-server.service`, which runs the `versions/buun` build.

The one-shot benchmark runner is:

```sh
scripts/run-llama-bench-matrix.py
```

It starts the server, waits for health, runs the prompt suite, stops the server, and repeats for every permutation of:

- models
- transports
- context sizes

The lower-level prompt-suite client is:

```sh
scripts/bench-llama-suite.py
```

You usually do not need to call it directly unless you already have a server running.

## One-shot matrix benchmark

Run the default matrix:

```sh
scripts/run-llama-bench-matrix.py
```

Defaults:

- models: `models/unsloth/Qwen3.6-35B-A3B-UD-IQ4_NL.gguf` (`Qwen3.6-35B-A3B-UD-IQ4_NL.gguf [35B total, A3B active, MoE]`)
- transports: `curl,pi-blank,pi-current`
- contexts: `32768,65536,131072,262144`

Results are written to:

```text
docs/benchmarks/matrix/<timestamp>/
```

Including:

- `bench.md` — markdown summary
- `all-results.json` — combined machine-readable results
- `raw/*.results.json` — raw prompt-suite outputs
- `raw/*.server.log` — server logs

### Configure the three main dimensions

Models are a comma-separated list. Each entry can be `label=path` or just `path`:

```sh
scripts/run-llama-bench-matrix.py \
  --models "qwen36=models/unsloth/Qwen3.6-35B-A3B-UD-IQ4_NL.gguf,other=/path/to/other.gguf"
```

Transports are a comma-separated list:

- `curl` — direct OpenAI-compatible HTTP calls to `llama-server`
- `pi-blank` — `pi -p` with a temporary blank `PI_CODING_AGENT_DIR` generated by the benchmark
- `pi-current` — `pi -p` using your current/default pi configuration

```sh
scripts/run-llama-bench-matrix.py \
  --transports "curl,pi-blank,pi-current"
```

Context sizes are also comma-separated:

```sh
scripts/run-llama-bench-matrix.py \
  --contexts "32768,65536,131072,262144"
```

Full example:

```sh
scripts/run-llama-bench-matrix.py \
  --models "qwen36=models/unsloth/Qwen3.6-35B-A3B-UD-IQ4_NL.gguf" \
  --transports "curl,pi-blank,pi-current" \
  --contexts "32768,65536" \
  --out-dir docs/benchmarks/my-run
```

If your current pi config should not save sessions during `pi-current` runs:

```sh
scripts/run-llama-bench-matrix.py \
  --transports "pi-current" \
  --contexts "32768" \
  --pi-current-no-session
```

If your current pi config points to the local server model alias and you want the benchmark to pass `--model selected` to pi, add:

```sh
--pi-current-pass-model
```

### Generate observations and conclusion with llama-server

By default, the matrix runner starts `llama-server` one more time after the benchmark and asks it to generate markdown observations and a conclusion from the collected metrics:

```sh
scripts/run-llama-bench-matrix.py \
  --models "qwen36=models/unsloth/Qwen3.6-35B-A3B-UD-IQ4_NL.gguf" \
  --transports "curl,pi-blank,pi-current" \
  --contexts "32768,65536,131072,262144"
```

To skip this analysis pass, use:

```sh
--no-llm-analysis
```

Defaults for the analysis pass:

- analysis model: first model in `--models`
- analysis context: largest context in `--contexts`

You can override them:

```sh
scripts/run-llama-bench-matrix.py \
  --models "qwen36=models/unsloth/Qwen3.6-35B-A3B-UD-IQ4_NL.gguf" \
  --transports "curl" \
  --contexts "32768" \
  --analysis-model qwen36 \
  --analysis-context 32768
```

The generated analysis is appended to `bench.md` under:

```md
## LLM-generated observations and conclusion
```

The raw generated text is also saved in `raw/analysis-*.analysis.md`.

## Direct HTTP and pi benchmarks

Use the matrix runner for repeatable runs:

```sh
scripts/run-llama-bench-matrix.py \
  --transports curl,pi-blank,pi-current \
  --contexts 32768,65536,131072,262144
```

For a smaller direct-HTTP-only run, set `--transports curl`. For pi-only runs, set `--transports pi-blank` or `--transports pi-current`.

## Output fields

Common fields:

- `label`: run label passed with `--label`
- `transport`: `http` or `pi`
- `wall_s`: wall-clock request time in seconds
- `content`: first 500 characters of the model response

HTTP-only fields:

- `prompt_tokens`
- `completion_tokens`
- `prompt_tps`
- `decode_tps`
- `finish_reason`
- `tool_calls`

Pi-only fields:

- `returncode`
- `stdout_chars`
- `stderr_chars`
- `tool_schema_sent`

Note: direct HTTP mode sends OpenAI tool schemas for the tool-call tests. Pi mode sends the same user prompts through `pi -p`; it does not send those custom tool schemas, so `tool_schema_sent` is `false`.
